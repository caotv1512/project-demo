## 2.2 · Khối `server` và `location`

**Cấu trúc file**

```nginx
server {                                  # một máy chủ ảo
    listen 80;                            # nghe cổng nào
    server_name _;                        # khớp tên miền nào

    location / {                          # xử lý đường dẫn nào
        root /usr/share/nginx/html;
        index index.html index.htm;
    }
}
```

**Lệnh**

```bash
nano /etc/nginx/conf.d/quickbite.conf
```
```bash
nginx -t
```

**Giải thích**

| Khối | Vai trò | Chỉ thị thường gặp |
|---|---|---|
| `server` | Máy chủ ảo theo **cổng và tên miền** | `listen`, `server_name`, `access_log`, `error_log` |
| `location` | Xử lý **một đường dẫn URI** | `root`, `index`, `proxy_pass` |

| Giá trị | Nghĩa |
|---|---|
| `listen 80` | Nhận HTTP trên cổng 80 |
| `server_name _` | Khớp request đi vào **IP VPS** (chưa có tên miền) |
| `location /` | Khớp mọi URI bắt đầu từ `/` |

**Ví dụ** — dán nguyên nội dung ở phần **Cấu trúc file** vào `nano`, lưu bằng `Ctrl+O` → `Enter` → `Ctrl+X`.

## 🧪 Thí nghiệm 1 — Cấu hình đúng mà vẫn trả `404`

Đây là cái bẫy **đầu tiên và im lặng nhất** của Nginx trên Ubuntu. Sandbox đã gỡ sẵn nguyên nhân để các bài sau chạy trơn tru, nên ta **tự dựng lại lỗi** để nhìn tận mắt.

**Cấu trúc** — Ubuntu nạp cấu hình từ **hai** thư mục, và chúng tranh nhau

```
/etc/nginx/nginx.conf
  ├── include conf.d/*.conf          ← file của bài học
  └── include sites-enabled/*        ← site mặc định của Ubuntu
                                        cả hai cùng: listen 80 + server_name _
```

> 📌 **Các lệnh dưới đây gõ BÊN TRONG VPS** — bạn vẫn đang ở trong phiên `docker exec -it vps11 bash` mở từ mục 2.1. Dấu nhắc phải là `root@quickbite-vps:~#`.

**Lệnh** — bật lại site mặc định của Ubuntu để tạo xung đột

```bash
ln -sf /etc/nginx/sites-available/default /etc/nginx/sites-enabled/default
```
```bash
nginx -t
```

**Ví dụ** — kết quả

```
[warn] conflicting server name "_" on 0.0.0.0:80, ignored
nginx: configuration file /etc/nginx/nginx.conf test is successful
```

**Giải thích**

| Chữ cần đọc | Nghĩa |
|---|---|
| `ignored` | Nginx **bỏ qua** một trong hai khối server trùng nhau |
| `successful` | Chỉ nói **cú pháp** đúng — **không** nói cấu hình của bạn đang chạy |
| Mức `[warn]` | Chỉ là cảnh báo, nên dòng kết luận vẫn là `successful` — rất dễ lướt qua |

**Lệnh** — nạp lại rồi gọi thử

```bash
nginx -s reload
```
```bash
sleep 2 && curl -s --max-time 5 http://localhost/ | grep -o '<title>.*</title>'
```

**Ví dụ** — nhận trang của **Ubuntu**, không phải trang của bạn

```
<title>Welcome to nginx!</title>
```

**Giải thích** — triệu chứng đổi theo cấu hình bạn đang có

| Cấu hình của bạn | Khi bị xung đột, bạn thấy |
|---|---|
| Chỉ có `location /` (như mục 2.2) | **Trang chào mừng của Ubuntu** — tưởng Nginx chạy đúng |
| Có `location` riêng (như mục 2.3, 3.1) | **`404 Not Found`** cho mọi đường dẫn của bạn |

> ⚠️ **Trường hợp đầu nguy hiểm hơn** — vì trông như mọi thứ đang chạy tốt. Bạn chỉ phát hiện ra khi gọi tới một đường dẫn cụ thể và nhận `404`.

**Lệnh** — sửa: gỡ site mặc định đi

```bash
rm -f /etc/nginx/sites-enabled/default
```
```bash
nginx -t && nginx -s reload
```
```bash
sleep 2 && curl -s -o /dev/null -w 'trang mac dinh: %{http_code}\n' http://localhost/
```

**Ví dụ** — không còn dòng `conflicting`, và `curl` trả `200`.

> ⚠️ **Trên VPS thật, site mặc định này BẬT SẴN.** Cài `nginx` bằng `apt` xong là nó có ngay. Vì vậy **việc đầu tiên cần làm** sau khi tạo file cấu hình của mình là:
>
> ```
> sudo rm /etc/nginx/sites-enabled/default
> ```
>
> Sandbox đã gỡ sẵn trong `Dockerfile` để các bài sau không vướng — nhưng ngoài đời bạn phải tự làm.

> 💡 **Bài học lớn hơn Nginx:** `nginx -t` trả về *successful* **không** có nghĩa là cấu hình của bạn đang có tác dụng. Nó chỉ kiểm tra **cú pháp**. Luôn đọc cả dòng `[warn]`, và luôn kiểm chứng bằng một request thật.

## 2.3 · Quy tắc so khớp `location`

**Cấu trúc**

```nginx
location [modifier] <đường-dẫn> { ... }
         └────┬───┘
       quyết định thứ tự ưu tiên
```

| Modifier | Loại so khớp | Ví dụ |
|---|---|---|
| `=` | **Chính xác, ưu tiên cao nhất** | `location = /favicon.ico` |
| `^~` | Tiền tố ưu tiên — **không quét Regex nữa** | `location ^~ /assets/` |
| `~` `~*` | Regular Expression (`~*` bỏ qua hoa thường) | `location ~* \.json$` |
| *(không có)* | Tiền tố mặc định | `location /api` |

**Lệnh**

```bash
exit
```
```bash
cd ~/Downloads/quickbite-demo/LAB_SS11
```
```bash
cat nginx-conf/02-thi-nghiem-location.conf | docker exec -i vps11 tee /etc/nginx/conf.d/quickbite.conf >/dev/null
```

> 💡 **Lệnh này KHÔNG in ra gì — đó là đúng.** Phần `>/dev/null` vứt bỏ những gì `tee` in ra màn hình, vì ta chỉ cần nó **ghi file**. Trong Unix, im lặng thường có nghĩa là thành công.
>
> **Kiểm chứng file đã được ghi:**
>
> ```
> docker exec vps11 wc -l /etc/nginx/conf.d/quickbite.conf
> ```
>
> Phải ra khoảng **25 dòng**. Ra `0` nghĩa là file rỗng — xem cảnh báo bên dưới.

> ⚠️ **Chạy riêng từng nửa của lệnh trên sẽ không ra kết quả như bạn tưởng:**
>
> | Chạy riêng | Chuyện gì xảy ra |
> |---|---|
> | `cat nginx-conf/02-...conf` | **In file ra màn hình** — vì không còn ống dẫn, stdout là màn hình |
> | `docker exec -i vps11 tee ...` | **Treo terminal** — `-i` giữ stdin mở, `tee` ngồi đợi bạn gõ |
>
> Nếu lỡ chạy nửa sau và bấm `Ctrl+D` để thoát, bạn vừa ghi một **file rỗng** — và nginx sẽ trả `404` vì không còn khối `server` nào. Chạy lại **nguyên câu lệnh có dấu `|`** là xong.
>
> **Dấu `|` làm hai việc:** nối output của `cat` vào input của `tee`, **và** báo hết dữ liệu (EOF) khi `cat` đọc xong — nhờ đó `tee` biết lúc nào dừng.

```bash
docker exec vps11 sh -c 'nginx -t && nginx -s reload'
```
```bash
for i in $(seq 1 10); do curl -s --max-time 2 http://localhost:8880/chinh-xac 2>/dev/null | grep -q 'chinh xac' && { echo "✅ cau hinh moi da co hieu luc"; break; }; sleep 1; done
```
```bash
for u in /chinh-xac /uu-tien/anh.json /bat-ky.json /uu-tien/trang; do printf '%-22s -> %s' "$u" "$(curl -s --max-time 5 http://localhost:8880$u)"; done
```

> ⚠️ **Vì sao phải có vòng lặp chờ ở trên?** `nginx -s reload` **không có hiệu lực tức thì** — nó để worker cũ xử lý nốt request đang chạy dở rồi mới tắt (xem mục 3.3). Gọi ngay sau khi reload rất dễ trúng worker cũ và nhận **`404`**, nhất là ở **lần reload đầu tiên** sau khi container vừa dựng.
>
> Đây không phải lỗi — đó chính là cơ chế *"reload không ngắt dịch vụ"* đang hoạt động.

**Giải thích** — kết quả phải ra đúng bảng này

| URI gọi | Khối được chọn | Vì sao |
|---|---|---|
| `/chinh-xac` | `1. = chinh xac` | `=` ưu tiên cao nhất |
| `/uu-tien/anh.json` | `2. ^~ tien to uu tien` | `^~` khớp rồi **dừng, không quét regex** |
| `/bat-ky.json` | `3. ~* regex` | Không tiền tố nào khớp |
| `/uu-tien/trang` | `2. ^~ tien to uu tien` | `^~` thắng tiền tố thường |

**Ví dụ** — trường hợp của slide 10

```bash

```

# BÀI 3 — CHUYỂN REQUEST VÀO API GATEWAY

> 📑 **Slide: Lesson 03 · Cấu hình Nginx chuyển tiếp request đến API Gateway** (slide 12–13)

## 3.1 · `proxy_pass` và bốn header

**Cấu trúc file**

```nginx
server {
    listen 80;
    server_name _;

    access_log /var/log/nginx/quickbite_access.log;
    error_log  /var/log/nginx/quickbite_error.log;

    location /api/ {
        proxy_pass http://quickbite5-gateway:8080;

        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

**Lệnh**

```bash
cat nginx-conf/01-quickbite-http.conf
```
```bash
cat nginx-conf/01-quickbite-http.conf | docker exec -i vps11 tee /etc/nginx/conf.d/quickbite.conf >/dev/null
```
```bash
docker exec vps11 sh -c 'nginx -t && nginx -s reload'
```
```bash
for i in $(seq 1 10); do curl -fsS --max-time 3 http://localhost:8880/api/v1/users >/dev/null 2>&1 && { echo "✅ cau hinh moi da co hieu luc"; break; }; sleep 1; done
```
```bash
curl -s --max-time 10 http://localhost:8880/api/v1/users | head -c 200; echo
```
```bash
for r in users restaurants orders notifications; do printf '  /api/v1/%-15s -> %s\n' "$r" "$(curl -s -o /dev/null -w '%{http_code}' --max-time 10 http://localhost:8880/api/v1/$r)"; done
```

**Giải thích**

| Chỉ thị | Chuyển tiếp gì | Thiếu thì sao |
|---|---|---|
| `proxy_pass` | Địa chỉ API Gateway đích | Không có proxy |
| `Host $host` | Tên miền request ban đầu | App sinh link sai tên miền |
| `X-Real-IP $remote_addr` | IP client kết nối tới Nginx | **Log ghi IP của Nginx cho mọi người** |
| `X-Forwarded-For $proxy_add_x_forwarded_for` | Chuỗi IP qua các proxy | Mất dấu vết client |
| `X-Forwarded-Proto $scheme` | `http` hay `https` | App sinh link `http://` trong trang HTTPS |

> ⚠️ **Dòng `proxy_pass` khác nhau giữa hai môi trường:**
>
> | Môi trường | Viết thế nào |
> |---|---|
> | 🌐 **VPS thật** | `proxy_pass http://127.0.0.1:8080;` |
> | **Sandbox** | `proxy_pass http://quickbite5-gateway:8080;` |
>
> Mọi dòng khác **giống hệt nhau**.

**Ví dụ** — kết quả

```
[{"id":1,"full_name":"Nguyen Van An","email":"an.nguyen@quickbite.vn","wallet_balance":425000}, ...]

  /api/v1/users           -> 200
  /api/v1/restaurants     -> 200
  /api/v1/orders          -> 200
  /api/v1/notifications   -> 200
```

## 4.1 · Tạo chứng chỉ tự ký

**Cấu trúc lệnh**

```
openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
            -keyout <file.key> -out <file.crt> -subj "/CN=<tên>"
             └──┬──┘      └─┬─┘
            khoá riêng   chứng chỉ
```

**Lệnh**

```bash
docker exec vps11 sh -c 'apt-get install -y -qq openssl >/dev/null 2>&1; mkdir -p /etc/nginx/ssl && openssl req -x509 -nodes -days 365 -newkey rsa:2048 -keyout /etc/nginx/ssl/quickbite.key -out /etc/nginx/ssl/quickbite.crt -subj "/CN=api.quickbite.local"'
```
```bash
docker exec vps11 ls -l /etc/nginx/ssl/
```

**Giải thích**

| Tham số | Nghĩa |
|---|---|
| `-x509` | Tạo chứng chỉ hoàn chỉnh, không phải yêu cầu ký |
| `-nodes` | Không đặt mật khẩu cho khoá riêng (Nginx cần đọc tự động) |
| `-days 365` | Hạn 1 năm |
| `-subj "/CN=..."` | Điền sẵn thông tin, khỏi hỏi tương tác |

| File | Là gì | Quyền |
|---|---|---|
| `quickbite.crt` | Chứng chỉ — ai xem cũng được | `644` |
| `quickbite.key` | **Khoá riêng** — tuyệt mật | `600` |

**Ví dụ**

```
-rw-r--r-- 1 root root 1139 quickbite.crt
-rw------- 1 root root 1704 quickbite.key
```

> 🌐 **Trên VPS thật** không làm bước này — Certbot sẽ cấp chứng chỉ thật (xem 4.4). Cách Nginx dùng hai file thì **y hệt**.

## 4.2 · SSL Termination và chuyển hướng 301

**Cấu trúc file** — hai khối `server`, mỗi khối một việc

```nginx
server {
    listen 80;
    server_name _;
    return 301 https://$host$request_uri;      # cổng 80 CHỈ redirect
}

server {
    listen 443 ssl;
    server_name _;

    ssl_certificate     /etc/nginx/ssl/quickbite.crt;
    ssl_certificate_key /etc/nginx/ssl/quickbite.key;

    location /api/ {
        proxy_pass http://quickbite5-gateway:8080;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

**Lệnh**

```bash
cat ~/Downloads/quickbite-demo/LAB_SS11/nginx-conf/03-quickbite-https.conf
```
```bash
cat ~/Downloads/quickbite-demo/LAB_SS11/nginx-conf/03-quickbite-https.conf | docker exec -i vps11 tee /etc/nginx/conf.d/quickbite.conf >/dev/null
```
```bash
docker exec vps11 sh -c 'nginx -t && nginx -s reload'
```
```bash
curl -s -o /dev/null -w 'ma: %{http_code} | chuyen toi: %{redirect_url}\n' --max-time 6 http://localhost:8880/api/v1/users
```
```bash
curl -sk --max-time 10 https://localhost:8443/api/v1/users | head -c 150; echo
```

**Giải thích**

| Chỉ thị | Tác dụng |
|---|---|
| `listen 443 ssl` | Nhận HTTPS |
| `ssl_certificate` | Đường dẫn chứng chỉ |
| `ssl_certificate_key` | Đường dẫn khoá riêng |
| `return 301 https://$host$request_uri` | Đẩy mọi request cổng 80 lên HTTPS, **giữ nguyên đường dẫn** |

| Mã | Nghĩa | Hệ quả |
|---|---|---|
| `301` | Chuyển **vĩnh viễn** | Trình duyệt nhớ, lần sau đi thẳng HTTPS |
| `302` | Chuyển tạm thời | Hỏi lại cổng 80 mỗi lần — dùng khi còn thử nghiệm |

**Ví dụ**

```
ma: 301 | chuyen toi: https://localhost/api/v1/users
[{"id":1,"full_name":"Nguyen Van An","email":"an.nguyen@quickbite.vn", ...
```

> 💡 **Cờ `-k` bỏ qua kiểm tra chứng chỉ** — cần vì chứng chỉ tự ký. 🌐 Với chứng chỉ Let's Encrypt thật thì **bỏ `-k` đi vẫn chạy**, đó chính là bằng chứng chứng chỉ hợp lệ.

## 5.1 · Đọc mã trả về để biết hỏng ở chặng nào

# PHỤ LỤC 2 · BẢNG LỖI

## 3 thí nghiệm trong tài liệu này

| # | Triệu chứng | Nguyên nhân | Sửa |
|---|---|---|---|
| 1 | `nginx -t` báo **successful** nhưng cấu hình không có tác dụng | Site mặc định Ubuntu cũng nghe cổng 80 | `rm /etc/nginx/sites-enabled/default` |
| 2 | Sửa cấu hình reload mà không đổi gì | Cú pháp sai nên Nginx **giữ cấu hình cũ** | `nginx -t` đọc lỗi rồi `nginx -t && nginx -s reload` |
| 3 | Đóng cổng Gateway mà Nginx vẫn gọi được | Nginx đi qua **mạng nội bộ** | Không phải lỗi — đó là mục tiêu |

## Lỗi khác

| Triệu chứng | Nguyên nhân thường gặp | Sửa |
|---|---|---|
| **`502 Bad Gateway`** | `proxy_pass` sai, hoặc backend chết | Gọi thẳng backend (5.3) |
| **`504 Gateway Timeout`** | Backend quá chậm hoặc treo | `docker compose logs api-gateway` |
| **`404` cho mọi đường dẫn ngay sau khi dựng lại sandbox** | `./tao-vps.sh` tạo container mới nên **site mặc định Ubuntu quay lại** và nuốt hết request | `docker exec vps11 rm -f /etc/nginx/sites-enabled/default` rồi reload |
| **`404` ngay sau khi `reload`, vài giây sau gọi lại thì được** | Worker cũ chưa tắt — `reload` **không** có hiệu lực tức thì | Dùng vòng lặp chờ ở mục 2.3, hoặc đợi 2–3 giây rồi gọi lại |
| Lệnh nạp cấu hình **không in ra gì** | `>/dev/null` vứt output của `tee` — **đây là bình thường** | Kiểm tra bằng `docker exec vps11 wc -l /etc/nginx/conf.d/quickbite.conf` |
| Terminal **treo** sau khi gõ `docker exec -i ... tee ...` | Chạy thiếu vế `cat ... \|` phía trước nên `tee` đợi bàn phím | `Ctrl+C` để huỷ, rồi chạy **nguyên câu lệnh** có dấu `\|` |
| File cấu hình **rỗng (0 dòng)** | Đã bấm `Ctrl+D` khi terminal treo → `tee` ghi 0 byte | Chạy lại nguyên câu lệnh có dấu `\|` |
| `404` cho mọi đường dẫn | Không `location` nào khớp | `nginx -T` xem khối nào đang chạy |
| URL bị cắt mất `/api` | `proxy_pass` có dấu `/` ở cuối | Bỏ dấu `/` cuối |
| API `.json` đột nhiên không qua proxy | Một `location ~* \.json$` giành mất | Đổi thành `location ^~ /api/` |
| `conflicting server name` | Hai khối `server` cùng `listen` và `server_name` | Gỡ bớt một cái |
| Lỗi cú pháp báo sai dòng | Thiếu `;` ở dòng **phía trên** | Nhìn dòng ngay trên dòng được báo |
| Trình duyệt báo chứng chỉ không hợp lệ | Chứng chỉ tự ký | Bình thường trong sandbox; VPS thật dùng Certbot |
| 🌐 Certbot không xác thực được tên miền | DNS chưa trỏ đúng, hoặc cổng 80 bị chặn | `dig +short <ten-mien>` trước |
| 🌐 Chứng chỉ hết hạn sau 90 ngày | Cổng 80 bị chặn nên không gia hạn được | Giữ cổng 80 mở |
| `access.log` trống | Request chưa tới Nginx | Kiểm tra tường lửa, cổng, DNS |
