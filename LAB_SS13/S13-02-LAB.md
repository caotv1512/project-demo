# BÀI 1 — NHÌN THẤY METRICS ĐẦU TIÊN

> 📑 **Slide: Lesson 01 · Metrics và kiến trúc hoạt động của Prometheus** (slide 4–9)

## 1.1 · Một metric trông như thế nào

**Cấu trúc một dòng metric**

```
http_server_requests_seconds_count{application="order-service",method="GET",status="200"} 7
└───────────────┬──────────────┘ └──────────────────┬─────────────────────────────────┘ │
           TÊN METRIC                            LABELS (nhãn)                        GIÁ TRỊ
```

**Giải thích**

| Thành phần | Vai trò |
|---|---|
| **Tên metric** | Đo cái gì |
| **Labels** | Phân biệt nguồn — service nào, đường dẫn nào, mã trả về nào |
| **Giá trị** | Một con số |
| *(Timestamp)* | Prometheus tự gắn khi thu thập, không nằm trong dòng này |

> 💡 **Cùng một tên metric + labels khác nhau = những chuỗi dữ liệu khác nhau.** Đó là cách Prometheus tách `GET /api/v1/orders` trả `200` khỏi cùng đường dẫn trả `500`.

## 1.2 · Bốn loại metric, phân biệt bằng hậu tố

**Cấu trúc**

| Loại | Đặc điểm | Hậu tố nhận biết | Ví dụ |
|---|---|---|---|
| **Counter** | **Chỉ tăng**, reset về 0 khi app khởi động lại | `_total`, `_count` | `http_server_requests_seconds_count` |
| **Gauge** | Tăng **và** giảm tự do | *(không có)* | `jvm_memory_used_bytes` |
| **Histogram** | Chia vào các khoảng rồi đếm | `_bucket` + `le=` | `http_server_requests_seconds_bucket` |
| **Summary** | Tính phân vị p50/p90/p99 ngay tại client | `quantile=` | `http_server_requests_seconds{quantile="0.99"}` |

**Giải thích** — quy tắc chọn

| Cần đo | Dùng |
|---|---|
| Tổng số request, tổng số lỗi | **Counter** |
| RAM đang dùng, số thread đang sống | **Gauge** |
| Phân bố độ trễ, gộp từ nhiều container | **Histogram** |
| Phân vị chính xác trên **một** instance | **Summary** |

> ⚠️ **Counter không cho bạn "tốc độ".** `http_..._count` chỉ là con số tích luỹ từ lúc khởi động. Muốn biết *"bao nhiêu request mỗi giây"* phải dùng hàm `rate()` của PromQL — ngoài phạm vi buổi này.

## 1.3 · Prometheus kéo, không đợi được đẩy

**Cấu trúc luồng scraping**

```
┌──────────────────────┐
│  Prometheus Server   │
│  (đọc prometheus.yml)│
└──────────┬───────────┘
           │ HTTP GET mỗi 15s   ← Prometheus CHỦ ĐỘNG gọi
   ┌───────┼────────────────┬──────────────────┐
   ▼       ▼                ▼                  ▼
user-service:8081   order-service:8083   node-exporter:9100
/actuator/prometheus  /actuator/prometheus    /metrics
           │
           ▼
      TSDB (lưu trên volume)
```

**Giải thích**

| | **Pull-based** (Prometheus) | **Push-based** |
|---|---|---|
| Ai chủ động | **Prometheus gọi vào** service | Service tự gửi ra |
| Target chết thì sao | **Biết ngay** — gọi không được | Im lặng, tưởng là không có dữ liệu |
| Hợp với | Service chạy lâu dài | Job chạy ngắn, serverless |

> 💡 **Ưu điểm lớn nhất của Pull:** Prometheus **tự biết target nào chết**, vì chính nó là bên gọi. Với Push thì "không nhận được gì" và "service đã chết" trông giống hệt nhau.

## 2.3 · Mở endpoint và gắn nhãn chung

**Cấu trúc file** — `order-service/src/main/resources/application.yml`

> ⚠️ **File này ĐÃ CÓ SẴN một khối `management:`** (đang để `include: health,info`).
> Hãy **sửa khối đó tại chỗ**, đừng dán khối dưới đây xuống cuối file — YAML không cho phép hai key `management` ở cùng cấp,
> app sẽ chết ngay khi khởi động với lỗi `DuplicateKeyException` và container rơi vào vòng restart.

```yaml

  endpoints:
    web:
      exposure:
        include: health,prometheus        ← chỉ mở đúng 2 endpoint cần
  endpoint:
    health:
      show-details: always
  metrics:
    tags:
      application: ${spring.application.name}   ← nhãn chung cho MỌI metric
```

**Lệnh**

| Cấu hình | Tác dụng |

## 🧪 Thí nghiệm 1 — Histogram **không** tự động xuất ra

# BÀI 3 — DỰNG PROMETHEUS BẰNG COMPOSE

> 📑 **Slide: Lesson 03 · Triển khai Prometheus bằng Docker Compose** (slide 18–21)

## 3.1 · File cấu hình `prometheus.yml`

**Cấu trúc file**

```yaml
global:
  scrape_interval: 15s                     # chu kỳ kéo metrics

scrape_configs:
  - job_name: quickbite-backend            # tên nhóm target
    metrics_path: /actuator/prometheus     # đường dẫn endpoint
    static_configs:
      - targets:
          - user-service:8081              # TÊN SERVICE, không phải IP
          - order-service:8083
```

**Lệnh**

```bash
cd ~/Downloads/quickbite-demo/LAB_SS13/monitoring
```
```bash
cat prometheus/prometheus.yml
```

**Giải thích**

| Khoá | Ý nghĩa |
|---|---|
| `scrape_interval` | Bao lâu kéo một lần |
| `job_name` | Tên nhóm — hiện thành label `job` trên mọi metric của nhóm |
| `metrics_path` | Đường dẫn endpoint. Spring Boot dùng `/actuator/prometheus`, Node Exporter dùng `/metrics` |
| `targets` | Danh sách `tên-service:cổng` |

**Ví dụ** — kiểm tra file có đủ hai job

```bash
grep -E 'job_name|metrics_path' prometheus/prometheus.yml
```

```
  - job_name: quickbite-backend
    metrics_path: /actuator/prometheus
  - job_name: vps-hardware
    metrics_path: /metrics
```

> 💡 **Vì sao dùng tên service chứ không phải IP?** IP container **đổi mỗi lần recreate**. Tên service thì không đổi, và Docker có DNS nội bộ phân giải nó — đúng cơ chế API Gateway đã dùng từ Session 05.

## 3.2 · File `docker-compose.yml`

**Cấu trúc file**

```yaml
services:
  prometheus:
    image: prom/prometheus:v2.45.0
    container_name: quickbite-prometheus
    volumes:
      - ./prometheus/prometheus.yml:/etc/prometheus/prometheus.yml   # mount file cấu hình
      - prometheus-data:/prometheus                                  # giữ lịch sử metrics
    # KHÔNG khai báo "ports" — xem cảnh báo bên dưới
    networks:
      - quickbite5-net

volumes:
  prometheus-data:

networks:
  quickbite5-net:
    external: true        # mạng do Session 05 tạo ra
```

**Lệnh**

```bash
cat docker-compose.yml
```
```bash
docker compose config --quiet && echo "Cu phap hop le"
```

**Giải thích**

| Khai báo | Tác dụng |
|---|---|
| Mount `prometheus.yml` | Đưa cấu hình vào container; sửa file ở máy là sửa luôn trong container |
| Volume `prometheus-data` | **Giữ lịch sử metrics** khi container bị xoá hoặc tạo lại |
| `external: true` | Dùng lại mạng sẵn có thay vì tạo mạng mới |
| **Không có `ports`** | Prometheus chỉ truy cập được **trong mạng nội bộ** |

**Ví dụ** — xác nhận không có khai báo `ports`

```bash
grep -c 'ports:' docker-compose.yml
```

```
0
```

# BÀI 4 — NODE EXPORTER GIÁM SÁT MÁY CHỦ

> 📑 **Slide: Lesson 04 · Node Exporter giám sát tài nguyên VPS** (slide 23–25)

## 4.1 · Khai báo Node Exporter

**Cấu trúc file** — phần `node-exporter` trong `docker-compose.yml`

```yaml
  node-exporter:
    image: prom/node-exporter:v1.6.0
    container_name: quickbite-node-exporter
    volumes:
      - /proc:/host/proc:ro        # :ro = CHỈ ĐỌC
      - /sys:/host/sys:ro
      - /:/rootfs:ro
    command:
      - --path.procfs=/host/proc
      - --path.sysfs=/host/sys
      - --path.rootfs=/rootfs
    networks:
      - quickbite5-net
```

**Giải thích**

| Mount | Đọc được gì |
|---|---|
| `/proc` | Tiến trình, RAM, CPU |
| `/sys` | Thiết bị và thông tin kernel |
| `/` | Dung lượng các phân vùng của host |

| Cờ | Tác dụng |
|---|---|
| `:ro` | **Chỉ đọc** — Node Exporter không ghi được gì vào host |
| `--path.procfs` … | Báo cho Node Exporter biết host nằm ở đâu bên trong container |

> ⚠️ **Cờ `:ro` là bắt buộc.** Node Exporter chỉ cần **đọc**. Mount ghi được là mở đường cho một container chỉnh sửa hệ điều hành của máy chủ.
