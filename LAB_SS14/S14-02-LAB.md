## 1.2 · Tạo file `docker-compose.yml`

**Lệnh** — bước 1: về đúng thư mục làm việc

```bash
cd ~/Downloads/quickbite-demo/LAB_SS14/grafana
```

**Lệnh** — bước 2: mở trình soạn thảo để tạo file

```bash

```

**Cấu trúc file** — gõ hoặc dán toàn bộ nội dung dưới đây vào, rồi lưu bằng `Ctrl+O` → `Enter` → `Ctrl+X`

```yaml
services:
  grafana:
    image: grafana/grafana:10.0.3
    container_name: quickbite-grafana
    ports:
      - "${GRAFANA_HOST_PORT:-3000}:3000"      # doi duoc bang bien moi truong
    volumes:
      - grafana-data:/var/lib/grafana          # giu dashboard qua cac lan restart
      - ./provisioning:/etc/grafana/provisioning:ro
    environment:
      - GF_SECURITY_ADMIN_PASSWORD=${GF_ADMIN_PASSWORD:-quickbite_lab_2026}
    networks:
      - quickbite5-net
    restart: unless-stopped

volumes:
  grafana-data:

networks:
  quickbite5-net:
    external: true
```

**Lệnh** — bước 3: kiểm tra file vừa tạo có đúng cú pháp YAML không

```bash
docker compose config --quiet && echo "Cu phap hop le"
```

**Giải thích**

| Khai báo | Tác dụng |
|---|---|
| `ports` | Grafana **có** đăng nhập nên publish ra được — khác Prometheus ở Session 13 |
| `grafana-data` | Mất volume là mất dashboard; metrics trong Prometheus thì vẫn còn |
| `external: true` | Dùng lại mạng Session 05 đã tạo, không tạo mạng mới |

**Ví dụ**

```

```

# PHẦN 3 — DASHBOARD GIÁM SÁT VPS

## 3.1 · PromQL: CPU đang sử dụng

**Cấu trúc câu lệnh**

```
100 - (avg by (instance) (irate(node_cpu_seconds_total{mode="idle"}[5m])) * 100)
```

**Lệnh**

```bash
curl -s -G "http://admin:quickbite_lab_2026@localhost:3000/api/datasources/proxy/uid/$DSUID/api/v1/query" --data-urlencode 'query=100 - (avg by (instance) (irate(node_cpu_seconds_total{mode="idle"}[5m])) * 100)' | python3 -c "
import json,sys
r=json.load(sys.stdin)['data']['result']
print('CPU dang dung: %.2f %%'%float(r[0]['value'][1]) if r else 'RONG')"
```

**Giải thích**

| Thành phần | Vai trò |
|---|---|
| `mode="idle"` | Lọc phần thời gian CPU rảnh |
| `100 - (...)` | Lấy phần bù để ra % CPU đang làm việc |
| `irate(...[5m])` | Tốc độ tức thời, nhạy hơn `rate()` với chỉ số biến động nhanh |

**Ví dụ**

```
CPU dang dung: 1.09 %
```

## 3.2 · PromQL: RAM đã sử dụng

**Cấu trúc câu lệnh**

```
(node_memory_MemTotal_bytes - node_memory_MemAvailable_bytes) / node_memory_MemTotal_bytes * 100
```

**Lệnh**

```bash
curl -s -G "http://admin:quickbite_lab_2026@localhost:3000/api/datasources/proxy/uid/$DSUID/api/v1/query" --data-urlencode 'query=(node_memory_MemTotal_bytes - node_memory_MemAvailable_bytes) / node_memory_MemTotal_bytes * 100' | python3 -c "
import json,sys
r=json.load(sys.stdin)['data']['result']
print('RAM da dung: %.2f %%'%float(r[0]['value'][1]) if r else 'RONG')"
```

**Giải thích**

Dùng `MemAvailable` chứ không `MemFree`, vì `MemAvailable` tính cả bộ nhớ đệm có thể giải phóng ngay.

**Ví dụ**

```
RAM da dung: 54.36 %
```

## 3.3 · PromQL: Disk đã sử dụng

**Cấu trúc câu lệnh** — bản cho VPS Linux thật

```
100 - (node_filesystem_avail_bytes{mountpoint="/"} * 100 / node_filesystem_size_bytes{mountpoint="/"})
```

**Lệnh** — xem máy bạn có mountpoint nào trước

```bash
curl -s -G "http://admin:quickbite_lab_2026@localhost:3000/api/datasources/proxy/uid/$DSUID/api/v1/query" --data-urlencode 'query=node_filesystem_size_bytes' | python3 -c "
import json,sys
r=json.load(sys.stdin)['data']['result']
print(sorted({x['metric'].get('mountpoint','?') for x in r}))"
```

**Giải thích**

> ⚠️ **Trên máy Mac/Windows, câu của slide trả về rỗng.** Node Exporter chạy trong Docker Desktop chỉ thấy filesystem của **máy ảo Docker**, và máy ảo đó không báo mountpoint `/`.

| Môi trường | Mountpoint dùng |
|---|---|
| VPS Linux thật | `/` |
| Docker Desktop trên Mac/Windows | `/var/lib/docker` |

**Lệnh** — bản chạy được khi học trên máy cá nhân

```bash
curl -s -G "http://admin:quickbite_lab_2026@localhost:3000/api/datasources/proxy/uid/$DSUID/api/v1/query" --data-urlencode 'query=100 - (node_filesystem_avail_bytes{mountpoint="/var/lib/docker"} * 100 / node_filesystem_size_bytes{mountpoint="/var/lib/docker"})' | python3 -c "
import json,sys
r=json.load(sys.stdin)['data']['result']
print('Disk da dung: %.2f %%'%float(r[0]['value'][1]) if r else 'RONG')"
```

**Ví dụ**

```
['/host_mnt', '/oldroot', '/run', '/tmp', '/var', '/var/lib', '/var/lib/docker']
Disk da dung: 10.50 %
```

## 3.5 · Dashboard trống sau khi import — chọn bộ lọc ở đầu trang

**Cấu trúc**

Dashboard `1860` không vẽ gì cho tới khi bạn chọn **máy nào** cần xem. Ở đầu trang có ba ô chọn:

```
job: [          ]   host: [          ]   node: [          ]
```

**Lệnh** — xem giá trị thật của máy bạn để chọn cho đúng

```bash
docker exec quickbite-prometheus wget -qO- "http://localhost:9090/api/v1/query?query=node_uname_info" | python3 -c "
import json,sys
for r in json.load(sys.stdin)['data']['result']:
    m=r['metric']
    print('job=%-16s host=%-16s node=%s' % (m.get('job'), m.get('nodename'), m.get('instance')))"
```

**Ví dụ**

```
job=vps-hardware     host=c3d6f4d3f22f   node=node-exporter:9100
```

**Giải thích**

Chọn đúng ba giá trị đó vào ba ô ở đầu dashboard, theo thứ tự từ trái sang phải — vì ô sau phụ thuộc ô trước.

| Ô | Chọn | Vì sao phụ thuộc nhau |
|---|---|---|
| `job` | `vps-hardware` | Lọc ra nhóm target phần cứng |
| `host` | mã máy, ví dụ `c3d6f4d3f22f` | Danh sách host chỉ hiện sau khi chọn `job` |
| `node` | `node-exporter:9100` | Danh sách node chỉ hiện sau khi chọn `host` |

> 💡 Chọn xong một lần rồi bấm biểu tượng **lưu** ở đầu dashboard, lần sau mở sẽ nhớ.

**Lệnh** — kiểm chứng panel sẽ ra số, không chỉ là dashboard tồn tại

```

**Ví dụ**

```

```

Đây là **đúng câu truy vấn** mà panel `CPU Busy` dùng, đã thay sẵn ba biến. Ra số nghĩa là panel chắc chắn vẽ được.

> ⚠️ **Ô `Root FS Used` báo `N/A` là bình thường khi học trên Mac hoặc Windows.**
> Node Exporter trong Docker Desktop không thấy mountpoint `/`. Trên VPS Linux thật thì ô này có số.

# PHẦN 5 — CẢNH BÁO KHI SERVICE DOWN

## 5.1 · Tạo Alert Rule

**Cấu trúc cấu hình**

```
Rule Name           : Service Down Alert
Data Source         : Prometheus
Query (A)           : up
Condition           : WHEN A IS BELOW 1
Evaluation Interval : 1m
Pending Period (For): 2m
Folder              : QuickBite Alerts
Contact Point       : Discord-Alerts
```

**Giải thích**

> ⚠️ **Slide ghi `up == 0` với điều kiện `IS ABOVE 0`. Cấu hình đó không bao giờ kêu.**
>
> `up == 0` là bộ lọc, trả về những chuỗi **có giá trị bằng 0**. Giá trị đưa sang bước điều kiện vì thế đúng bằng `0`, mà `0 > 0` là sai. Alert đứng mãi ở `Normal` dù service đã chết, và **không có thông báo lỗi nào**.

| Cách viết | Kết quả |
|---|---|
| Query `up == 0`, điều kiện `IS ABOVE 0` | ❌ không bao giờ Firing |
| Query `up`, điều kiện `IS BELOW 1` | ✅ đúng, giữ được nhãn `instance` |
| Query `count(up == 0)`, điều kiện `IS ABOVE 0` | ✅ đúng nhưng mất nhãn `instance` |

**Ví dụ** — chứng minh giá trị trả về đúng bằng 0

```bash
curl -s -G "http://admin:quickbite_lab_2026@localhost:3000/api/datasources/proxy/uid/$DSUID/api/v1/query" --data-urlencode 'query=up == 0' | python3 -c "
import json,sys
r=json.load(sys.stdin)['data']['result']
for x in r: print(x['metric'].get('instance'),'-> gia tri =',x['value'][1])
print('(rong nghia la moi service dang song)') if not r else None"
```
